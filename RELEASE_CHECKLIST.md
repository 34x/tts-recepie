# Prepare a project for public release

> Every line is a checkbox (☐) you tick as you go. Lines marked 🔴 are the
> **must-never-go-to-the-web** gate — if any of these isn't ✅, do **not** publish.

## 1. Scope & inventory
- ☐ Decide what is public vs. private (full repo vs. a subset)
- ☐ List every file currently tracked
- ☐ Classify each as: **keep / make template / exclude / delete**

## 2. 🔴 Secrets & confidential data — MUST-NEVER-TO-THE-WEB
- ✅ **🔴 Scan all tracked files for API keys, tokens, passwords, private keys**
- ✅ **🔴 Confirm `.env` and every secrets file is NOT committed**
- ✅ **🔴 Confirm no secrets are hardcoded in source**
- ✅ **🔴 Confirm no PII** (real names, emails, usernames, internal hostnames, IPs) — no emails/IPs/usernames in tracked files or history; the real name previously in the `LICENSE` header was removed
- ✅ **🔴 Confirm no personal reference data** (voice/audio clips, user data, uploads) — `refs/out_english.wav` is **synthetic**, generated by Qwen TTS from instructions (not a real person, not private) → safe to publish
- ☐ **🔴 Check full git history for anything ever committed, then remove it**
- ☐ **🔴 Rotate any key that may have appeared in history**

## 3. 🔴 Sensitive binaries & data — MUST-NEVER-TO-THE-WEB
- ✅ **🔴 Confirm no model weights / large binaries are committed**
- ✅ **🔴 Confirm no generated output, logs, or build artifacts are committed**
- ✅ **🔴 Confirm no caches** (`venv`, `node_modules`, `__pycache__`, etc.)

## 4. Machine / infra identity
- ✅ Remove or parameterize local paths (home dirs, internal mounts) — only generic `/home/user/…` in `.env.example` and `~/.cache/…` refs; no real home dirs (real `.env` is untracked)
- ✅ Remove internal hostnames/IPs and device mounts from configs — only self-referential `localhost`/`127.0.0.1`; `/dev/kfd`, `/dev/dri` are standard GPU device paths
- ✅ Ship only templates + example files, not rendered machine-specific files — only `tts-dev-pod.yaml.tmpl` tracked; the rendered manifest is gitignored and dockerignored

## 5. License & legal
- ✅ Choose a license and add `LICENSE` matching intent — GPL‑3 in place; author attribution anonymized (real name removed from header)
- ☐ Verify third-party components/dependencies are compatible with it
- ☐ Add attribution / `NOTICE` for borrowed code or data
- ☐ Confirm you own/are allowed to publish every bundled asset

## 6. Documentation & polish
- ☐ Rewrite `README.md` for an external reader
- ☐ Decide fate of internal notes and dev-only scripts
- ☐ Add `CODE_OF_CONDUCT`, `SECURITY.md`, `CONTRIBUTING`, `CHANGELOG`
- ☐ Ensure "how to run" works on a clean machine (no local-path assumptions)

## 7. Packaging & tooling
- ☐ Ensure `.gitignore` covers all generated/sensitive files
- ✅ Add `.dockerignore` if containerized — added root `.dockerignore` (excludes `.env`, `output/`, caches, weights, rendered manifest; keeps `refs/out_english.wav`)
- ☐ Add `.gitattributes` / decide LFS policy
- ☐ Pin and verify dependency versions

## 8. CI & gates
- ☐ Add a secret-scanning step (e.g. `gitleaks`/`trufflehog`)
- ☐ Add a lint/test job
- ☐ Add a build/smoke-test job

## 9. Final verification before push
- ☐ Re-read the exact file list that will be pushed
- ☐ Re-scan history one last time
- ☐ Clone to a clean machine and confirm it builds + runs
- ☐ Confirm target repo, visibility, and default branch
- ☐ Tag a release version
